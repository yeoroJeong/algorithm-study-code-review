# 코드 리뷰 가이드

## 리뷰 우선순위

### 1. 정답성과 예외 처리

- 입력 범위를 벗어나는 경우가 없는가?
- 경계값을 올바르게 처리하는가?
- 중복 방문이나 무한 반복 가능성이 없는가?
- 문제 조건을 빠뜨리지 않았는가?

### 2. 시간·공간 복잡도

- 제한 시간 안에 동작할 수 있는가?
- 불필요하게 배열을 복사하거나 반복 탐색하지 않는가?
- 더 적합한 자료구조를 사용할 수 있는가?

### 3. 가독성

- 변수와 함수 이름이 역할을 설명하는가?
- 중첩이 지나치게 깊지 않은가?
- 반복되는 로직을 함수로 분리할 수 있는가?
- 주석이 코드 자체로 알 수 없는 이유를 설명하는가?

### 4. 다른 접근

- 구현, 완전탐색, DFS/BFS, 그리디, DP 등 다른 방법이 가능한가?
- 현재 방법과 다른 방법의 장단점은 무엇인가?
- Python의 내장 함수나 자료구조로 간결하게 만들 수 있는가?

## 리뷰 표현

```text
[MUST] 이 조건에서는 인덱스 범위를 벗어날 수 있습니다.
[SUGGEST] visited를 set으로 두면 좌표 확인 의도가 더 분명할 것 같습니다.
[QUESTION] 이 위치에서 배열을 복사한 이유가 무엇인가요?
[GOOD] 방향 배열을 사용해 중복 로직을 잘 줄였습니다.
[NOTE] deque의 popleft()는 list.pop(0)보다 효율적입니다.
```

## 좋은 리뷰의 기준

- 사람보다 코드를 대상으로 이야기합니다.
- 수정 이유와 예상 효과를 함께 설명합니다.
- 취향 차이와 오류를 구분합니다.
- 잘한 부분도 구체적으로 언급합니다.
- 정답을 바로 주기보다 작성자가 생각할 수 있는 질문을 남깁니다.
