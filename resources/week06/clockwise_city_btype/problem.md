# Clockwise City

> SSAFY/SWEA User Problem 형식을 참고해 만든 알고리즘 스터디용 B형 복원 문제이다.

## 문제 설명

`N × N` 크기의 도시에 직사각형 건물이 순차적으로 추가된다.

각 건물이 설치되면 건물의 바로 바깥쪽 1칸을 따라 **시계 방향 일방통행 도로**가 생성된다. 이후 다른 건물이 추가되어 도로가 겹치면 기존 도로는 사라지지 않고, 해당 칸이 지원하는 이동 방향이 누적된다.

자동차는 한 건물에서 출발해 다른 건물까지 이동한다. `move()` 호출에는 반드시 방문해야 하는 경유 건물들이 주어질 수 있으며, **경유 순서는 자유롭지만 모든 경유 건물을 한 번 이상 방문해야 한다.**

현재까지 설치된 모든 건물과 도로를 기준으로 최소 이동 거리를 구하라.

---

## 1. 도시와 좌표

도시의 좌표는 다음과 같다.

```text
0 ≤ row < N
0 ≤ col < N
```

`N`은 `init()` 호출 시 주어지며 `N ≤ 50`이다.

모든 건물과 해당 건물의 바깥 도로는 보드 범위 안에 주어진다.

---

## 2. 건물

건물의 왼쪽 위 좌표가 `(mRow, mCol)`, 높이가 `mHeight`, 너비가 `mWidth`이면 건물 영역은 다음과 같다.

```text
mRow ≤ row < mRow + mHeight
mCol ≤ col < mCol + mWidth
```

각 건물은 서로 다른 `mID`를 가진다. 한 번 추가된 건물은 삭제되지 않는다.

---

## 3. 건물 외곽 도로

건물 영역이 아래와 같다고 하자.

```text
        ┌───────────┐
        │           │
        │   BUILD   │
        │           │
        └───────────┘
```

건물이 추가되면 건물로부터 바깥쪽 1칸에 다음과 같은 일방통행 도로가 생긴다.

```text
          → → → → → →
        ┌─────────────┐
      ↑ │             │ ↓
      ↑ │    BUILD    │ ↓
      ↑ │             │ ↓
        └─────────────┘
          ← ← ← ← ← ←
```

건물의 위치가 `(r, c)`, 높이가 `h`, 너비가 `w`일 때 외곽 도로의 위치와 지원 방향은 다음과 같다.

- 위쪽 도로: `row = r - 1`, `c - 1 ≤ col ≤ c + w`, `RIGHT`
- 오른쪽 도로: `col = c + w`, `r - 1 ≤ row ≤ r + h`, `DOWN`
- 아래쪽 도로: `row = r + h`, `c - 1 ≤ col ≤ c + w`, `LEFT`
- 왼쪽 도로: `col = c - 1`, `r - 1 ≤ row ≤ r + h`, `UP`

따라서 한 건물의 네 외곽 코너는 두 개의 방향을 동시에 지원한다.

도로에서 인접한 한 칸으로 이동하는 비용은 `1`이다.

---

## 4. 도로 중첩

새 건물에 의해 생성된 도로가 기존 도로와 같은 좌표를 사용할 수 있다.

이 경우 이동 가능 방향은 **누적**된다.

예를 들어 기존에 어떤 칸이 `RIGHT`를 지원하고 있었는데 새 건물에 의해 `DOWN`이 추가되면 해당 칸은 다음 두 방향을 모두 지원한다.

```text
RIGHT + DOWN
```

기존 방향을 새로운 방향으로 덮어쓰면 안 된다.

---

## 5. 진행 방향과 방향 전환

자동차는 항상 현재 진행 방향을 가진다.

일반 도로에서는 진행 방향을 변경할 수 없다.

현재 위치가 어떤 건물의 **외곽 코너**인 경우에만 방향을 변경할 수 있다.

- 코너가 아닌 칸: 현재 진행 방향으로만 이동할 수 있다.
- 코너인 칸: 현재 칸이 지원하는 방향 중 하나를 선택해 이동할 수 있다.

단, 선택한 방향 `d`로 다음 칸으로 이동하려면

1. 현재 칸이 `d`를 지원하고,
2. 다음 칸 역시 `d`를 지원해야 한다.

도로가 단순히 교차한다는 이유만으로 코너가 아닌 위치에서 방향을 바꿀 수는 없다.

여러 건물이 겹쳐 같은 좌표에 여러 방향이 추가되거나 새로운 코너가 추가될 수 있다. 따라서 새 건물이 설치되면 이전에는 불가능했던 경로가 가능해질 수 있다.

---

## 6. 건물 출입구

각 건물에는 **하나의 출입구**가 있다.

출입구는 건물의 왼쪽 위 좌표를 기준으로 한 상대 좌표 `(mRelRow, mRelCol)`로 주어진다.

실제 출입구 좌표는 다음과 같다.

```text
(mRow + mRelRow, mCol + mRelCol)
```

출입구는 항상 건물의 네 변 중 하나에 존재하며 **건물의 꼭짓점에는 주어지지 않는다.**

출발할 때와 도착할 때 동일한 출입구를 사용한다.

### 출입구와 연결되는 외곽 도로

출입구가 어느 면에 있는지에 따라 연결되는 외곽 도로 위치와 진행 방향이 결정된다.

| 출입구 위치 | 연결되는 외곽 도로 | 도로 진행 방향 |
|---|---|---|
| 위쪽 변 | 출입구 바로 위 1칸 | RIGHT |
| 오른쪽 변 | 출입구 바로 오른쪽 1칸 | DOWN |
| 아래쪽 변 | 출입구 바로 아래 1칸 | LEFT |
| 왼쪽 변 | 출입구 바로 왼쪽 1칸 | UP |

건물과 외곽 도로 사이를 이동하는 비용은 `1`이다.

즉 건물에서 나올 때에는 우회전하여 해당 건물의 시계 방향 도로에 진입하고, 건물에 들어갈 때에도 같은 진행 방향에서 우회전하여 출입구로 들어간다.

---

## 7. 출발 건물

`move(mStartID, ...)`가 호출되면 자동차는 `mStartID` 건물 내부에서 출발한다.

출입구를 통해 외곽 도로로 나가는 비용 `1`이 최초 이동 거리에 포함된다.

도로에 진입한 직후 진행 방향은 해당 출입구가 위치한 면의 시계 방향 도로 방향이다.

---

## 8. 경유 건물 방문

필수 경유 건물을 방문하려면 해당 건물의 출입구와 연결된 외곽 도로 칸에 **올바른 진행 방향**으로 도착해야 한다.

그 상태에서

```text
외곽 도로 → 건물 내부 → 동일한 출입구 → 외곽 도로
```

순서로 방문한다.

건물로 들어가는 비용은 `1`, 다시 나오는 비용도 `1`이므로 경유 건물 하나를 실제로 방문하고 같은 도로 상태로 복귀하는 비용은 총 `2`이다.

경유 건물을 방문한 뒤의 외곽 도로 위치와 진행 방향은 방문 직전과 동일하다.

경유 건물 주변을 단순히 지나가는 것은 방문으로 인정하지 않는다.

---

## 9. 도착 건물

모든 필수 경유 건물을 방문한 뒤 `mEndID` 건물의 출입구로 들어가면 이동이 완료된다.

도착 건물의 출입구와 연결된 외곽 도로 칸에 올바른 진행 방향으로 도착한 뒤 건물 안으로 들어가는 비용 `1`이 최종 이동 거리에 포함된다.

모든 필수 경유 건물을 방문하지 않은 상태에서 도착 건물을 지나가는 것은 이동 완료로 인정하지 않는다.

---

# API

참가자는 다음 세 함수를 구현한다.

```cpp
void init(int N);

void addBuilding(
    int mID,
    int mRow,
    int mCol,
    int mHeight,
    int mWidth,
    int mRelRow,
    int mRelCol
);

int move(
    int mStartID,
    int mEndID,
    int M,
    int mStopover[]
);
```

---

## `void init(int N)`

각 테스트 케이스의 처음에 한 번 호출된다.

기존의 모든 건물 및 도로 정보를 제거하고 `N × N` 도시를 초기화한다.

### Parameters

- `N`: 도시의 한 변 길이 (`5 ≤ N ≤ 50`)

---

## `void addBuilding(...)`

ID가 `mID`인 건물을 추가한다.

### Parameters

- `mID`: 건물 ID
- `mRow`, `mCol`: 건물의 왼쪽 위 좌표
- `mHeight`, `mWidth`: 건물의 높이와 너비
- `mRelRow`, `mRelCol`: 건물 왼쪽 위를 기준으로 한 출입구의 상대 좌표

건물이 추가되는 즉시 외곽 도로와 네 코너가 활성화된다.

기존 도로와 겹치는 경우 이동 가능 방향은 누적된다.

### 반환값

없음.

---

## `int move(...)`

`mStartID` 건물에서 출발해 `mEndID` 건물로 이동한다.

`mStopover`에 주어진 모든 건물을 반드시 한 번 이상 방문해야 한다.

경유 건물의 방문 순서는 자유롭다.

### Parameters

- `mStartID`: 출발 건물 ID
- `mEndID`: 도착 건물 ID
- `M`: 필수 경유 건물 수 (`0 ≤ M ≤ 5`)
- `mStopover[i]`: 필수 경유 건물 ID (`0 ≤ i < M`)

### 반환값

조건을 만족하는 최소 이동 거리를 반환한다.

이동할 수 없다면 `-1`을 반환한다.

---

# 제한 사항

- `5 ≤ N ≤ 50`
- 한 테스트 케이스의 `addBuilding()` 호출 횟수는 최대 `100`회이다.
- 한 테스트 케이스의 `move()` 호출 횟수는 최대 `200`회이다.
- `0 ≤ M ≤ 5`
- 건물 ID는 서로 다르다.
- `move()`에 전달되는 모든 건물은 호출 시점에 이미 추가되어 있다.
- `mStartID`, `mEndID`, `mStopover[]`의 ID는 서로 다르다.
- 건물의 출입구는 건물의 변 위에 있으며 꼭짓점에는 주어지지 않는다.
- 모든 건물 및 해당 외곽 도로는 보드 범위 내에 주어진다.
- 건물은 삭제되지 않는다.
- `addBuilding()`과 `move()`는 `init()` 이후 임의의 순서로 호출될 수 있다.
- C++ 실행 시간 제한은 `1초`이다.

---

# 제공 코드 입력 형식

실제 참가자 코드는 표준 입력을 직접 처리하지 않는다. 제공되는 `main.cpp`가 입력을 읽고 위 API를 호출한다.

명령 번호는 다음과 같다.

```text
100 : init
200 : addBuilding
300 : move
```

입력 첫 줄에는 테스트 케이스 수 `T`와 각 테스트 케이스의 배점 `MARK`가 주어진다.

각 테스트 케이스의 첫 줄에는 명령의 수 `Q`가 주어진다.

### INIT

```text
100 N
```

### ADD

```text
200 mID mRow mCol mHeight mWidth mRelRow mRelCol
```

### MOVE

```text
300 mStartID mEndID M [M개의 경유 건물 ID] 정답
```

`main.cpp`는 참가자가 구현한 `move()`의 반환값과 입력 마지막에 주어진 정답을 비교한다.

테스트 케이스의 모든 `move()` 결과가 일치하면 `MARK`, 하나라도 틀리면 `0`점을 출력한다.

---

# 출력 형식

각 테스트 케이스마다 다음 형식으로 점수를 출력한다.

```text
#테스트케이스번호 점수
```

예시:

```text
#1 100
#2 100
```

---

# 짧은 디버깅 예제

첫 번째 테스트 케이스는 핵심 동작을 빠르게 확인할 수 있도록 7개 명령으로 구성한다.

```text
7
100 30
200 1 5 5 5 5 0 2
200 3 5 17 5 5 0 2
300 1 3 0 -1
200 2 5 11 5 5 0 2
300 1 3 0 14
300 1 3 1 2 16
```

각 `move()`의 예상 반환값은 호출 순서대로 다음과 같다.

```text
-1
14
16
```

- 첫 번째 `-1`: 건물 1과 건물 3 사이의 도로가 아직 연결되지 않았다.
- 두 번째 `14`: 건물 2가 추가되면서 건물 1에서 건물 3으로 이동할 수 있다.
- 세 번째 `16`: 건물 2를 경유하려면 외곽 도로에서 건물로 들어갔다가 다시 나와야 하므로 기본 이동 거리보다 비용 `2`가 추가된다.

제공 코드용 입력에서는 각 `300` 명령의 마지막 숫자가 채점에 사용하는 예상 반환값이다. 전체 프로그램은 개별 반환값 대신 테스트 케이스 점수인 `#1 100`을 출력한다.
